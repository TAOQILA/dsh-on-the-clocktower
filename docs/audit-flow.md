# 现状流程说明（供角色审核用）

本文件描述「血染钟鱼」当前**已经由代码实现**的机制。审核角色时，请对照这些机制，判断该角色的能力能否在当前流程里被正确执行；不能的，就是冲突点。

## 1. 一局的生命周期
- setup（建局）→ night（夜）→ day（白天）→ nomination（提名阶段）→ vote/处决 → night …
- 阶段由 state.phase 表示，允许值：setup / night / dawn / day / nomination / vote / ended。
- 入夜：setPhase(night)，night += 1。
- 天亮：setPhase(day) 时，系统**自动**在公聊播报「天亮了，第 N 天开始。昨夜死亡：X 号 名、…。」或「昨夜是平安夜，没有人死亡。」，随后清空 state.nightDeaths。
- 处决后进入夜晚（night += 1）。

## 2. 发牌（程序机械发牌，roleMode=program 时）
- 按人数配比 compositionFor(n)：[镇民, 外来者, 爪牙, 恶魔]。5人[3,0,1,1] 6人[3,1,1,1] 7人[5,0,1,1] 8人[5,1,1,1] 9人[5,2,1,1] 10~12人[7,2,1,1] 13人[9,2,1,1] 14~15人[9,3,1,1]。
- 已实现的方括号解析（bracketSpec）：
  - [+N 爪牙] / [-N 爪牙]
  - [+N 外来者] / [-N 外来者]
  - [+0~2 村夫] 这类范围角色：随机取 min~max 个
  - [+国王] / [+落难少女] 这类指定角色：必须进场
  - [邪恶角色全部邻座]、[提线木偶会与恶魔邻座]：座位编排
  - [无恶魔在场]、[无邪恶角色在场]、[多数玩家为军团]、[外来者数量任意]
  - 命中上述标签的角色会被排除出牌池或特殊处理，并写进 dealRoles 返回的 notes。
- 发牌后自动 dealEvilInfo：爪牙收到「你的同伴是：<恶魔>」；恶魔收到「你的爪牙是：…」加「可以伪装成的三个身份：…」（从剧本镇民+外来者里排除在场角色随机取 3）。
- 每个座位收到私聊「你的角色是【X】。」（giveInfo 有去重，同一文本不会重复发）。

## 3. 夜晚
- 说书人（Agent）按 data/nightorder.json 的顺序表逐项处理，每项附角色能力原文。
- 需要玩家自己选目标的角色，说书人必须先私聊问「你想选择谁」，收到答复再结算。
- 说书人禁止在公聊透露唤醒了谁、给了谁什么信息、谁是什么角色。
- 说书人输出 JSON：{think, say, info[], markers[], deaths[], nextPhase, voteTarget, resolveVote}。nextPhase 写 day 即推进到白天。

## 4. 信息与可见性
- state.info[seat] = [{text, night, day, phase}]，夜里给的条目在天亮前不能公开讨论。
- state.markers[seat] 是说书人私有：非说书人视角在 /api/game 里被清空。
- 死亡：kill() 只在夜里把座位 push 进 nightDeaths 并记日志；公开死亡播报在 setPhase(day)。
- 聊天：town 全员可见；private 只有收发双方 + 说书人（且说书人只看与自己有关的私聊）。

## 5. 提名与投票（已实现，engine.cjs）
- 每人每天 1 次提名权（usedNom）、1 次被提名权（usedTarget）；死者可发起提名；可提名自己；同一时间只能有一项提名。
- 流程：nomPropose（提名+理由）→ nomNext → nomSpeech(reason) → nomSpeech(defense) → 投票 nomHand → 时钟轮转 nomClockBegin/nomTick 逐格锁定 → nomResolve 统计 → nomClose（处理队列下一项）。
- 上处决台条件：票数严格高于当天此前最高、≥1 票、且票数 ≥ 存活人数的一半。
- 加权票（voteWeight）：能力含「投票算作三票」→3；「投票算作两票」/「每次投票可投两票」→2；「投票会被算作负数」→-1；markers 含「讷帽」→2；否则 1。
- 管家：markers 里要有「主人:N」（N 为 1 起座位号），主人没举手时管家的举手会被拒绝。
- 狂热者：存活 ≥5 时必须投票，弃权被拒。
- 街头风琴手：存活且未中毒/醉酒时 secretBallot=true → 票数与是否上处决台都不公开，只宣布「票数已秘密统计」。
- 军团：若投票的赞成者全部是邪恶玩家，则投票无效（votes=0）。
- 死者持有 1 张死亡票（deadVoteUsed），用掉即失去。
- 提名阶段收尾：nomFinish 处决当天处决台上的人（没有则无人被处决），然后进入夜晚。

## 6. 胜负
- checkWin：恶魔出局 → 善良胜；存活 ≤2 且恶魔仍在 → 邪恶胜。终局后 /api/game 公开全部角色。

## 7. 没有代码实现、全靠说书人 Agent 判断的部分
- 绝大多数角色能力的具体效果没有硬编码。说书人只拿到：规则要点、本剧本角色能力速览、角色细则、《夜晚行动顺序》表（含能力原文）、全场座位与真相（含每人角色与能力原文）。
- 说书人靠 LLM 判断结算。所以「冲突」主要指：
  ① 该角色的能力与上面这些硬编码机制直接矛盾（例如程序自动做的事与能力冲突）；
  ② 该角色的能力需要某种状态/交互通道，而当前流程里没有（例如无法询问某玩家、无法设置某个标记、无法改变票权、无法修改死亡判定）；
  ③ 该角色的能力会改变基础规则（投票权、提名权、处决、死亡、胜负），当前硬编码会覆盖它。

## 8. 输出格式（每个角色一行，Markdown 表格）
