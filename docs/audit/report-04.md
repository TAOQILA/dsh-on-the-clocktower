## 需要改动的地方

### 一、engine.cjs —— 复活（教授）【高】

1. 新增 \`function revive(id, seat)\`：校验 \`s.alive[seat]===false\`；置 \`s.alive[seat]=true\`；从 \`s.markers[seat]\` 移除 \`死亡\`；清 \`s.deadVoteUsed[seat]\`（复活者恢复投票权）；记录到新的 \`s.dawnRevivals\` 数组；调用 \`checkWin(id)\` 重新评估（复活可能改变存活人数）。
2. \`setPhase\`（engine.cjs:95，天亮播报在 113-122）里的播报文本要加复活：\`昨夜死亡：…；复活：X 号 …。\`（暂无复活时保持现状）。
3. \`module.exports\`（engine.cjs:951-957）导出 revive。

### 二、engine.cjs —— 处决前免死裁定（茶艺师 / 和平主义者 / 弄臣 / 旅店老板）【高】

1. \`execute(id, seat)\`（engine.cjs:176-182）目前无条件 \`s.alive[seat]=false\`。应在置死前调用一个 \`canDie(s, seat, 'execution')\`：若 \`s.markers[seat]\` 命中「免死」「不会死亡」「弄臣未用」等约定标记，则不改 alive、不 push 死亡，改为公聊播报「今天没有人死亡」，并（弄臣场景）追加「弄臣已用」标记。
2. 更稳的做法是拆成两步：\`nomFinish\`（engine.cjs:899-912）只把 \`onBlock\` 目标写入 \`s.pendingExec\` 并返回 \`{needConfirm:true, target}\`，由说书人回包确认后再真正 execute。这样「可能不会死亡」这种说书人自由裁量才有落点。
3. \`kill(id, seat, reason)\`（engine.cjs:227-238）同样加一次 \`canDie\` 检查，覆盖旅店老板/茶艺师的夜间免死；返回 \`{ok:true, saved:true}\` 便于 agents.cjs 计数。

### 三、engine.cjs —— 标记语义（全部 10 个角色都受益）【中→高影响面】

1. \`toggleMarker\`（engine.cjs:287-292）是**切换**语义：\`indexOf\` 命中就 splice 删除。说书人重复下发「醉酒」会把醉酒状态取消掉，这是持续性状态的定时炸弹。建议新增 \`setMarker(id, seat, marker)\`（去重后 push）与 \`clearMarker(id, seat, marker)\`，并让 agents.cjs 的 markers 通道改用 setMarker；toggleMarker 保留给管理员手动用。
2. 标记需要过期：给 state 加 \`s.markerUntil = { [seat]: { [marker]: {day, phase} } }\`，在 \`setPhase\` 里按 day/phase 清理（对应「到下个黄昏」「三天三夜」「直到明天黄昏」）。至少要在 \`toggleMarker\`/\`setMarker\` 里支持 \`{marker, untilDay, untilPhase}\` 形式。
3. 约定标记文案（写进 agents.cjs 的提示词并落到代码正则）：
   - \`醉酒:至第N天黄昏\`、\`中毒:至第N夜\`
   - \`被保护:第N夜\`、\`免死:第N夜\`
   - \`弄臣已用\`、\`教授已用\`、\`侍臣已用\`（限次能力）
   - \`驱魔人昨夜选择:N\`（驱魔人不重复选人的持久状态）

### 四、engine.cjs —— 票权与醉酒/中毒（旅店老板、侍臣）【中】

\`voteWeight(s, seat)\`（engine.cjs:687-696）只看能力原文，不看状态。应在函数开头加：若 \`s.markers[seat]\` 命中 \`/中毒|醉酒/\`，直接 \`return 1\`（能力失效）。否则「让官员醉酒的侍臣」「让报丧女妖醉酒的旅店老板」在计票上等于没生效。
同一处理应同步到 \`secretBallot\`（engine.cjs:702-710，它已经检查了中毒/醉酒，可作为写法参考）与 \`butlerMaster\`（醉酒的管家不应受主人约束，反之亦然）。

### 五、agents.cjs —— 新增 revive 通道（教授）【高】

1. \`parseReply\`（agents.cjs:633-655）的 empty 结构与返回对象里加 \`revives: []\`，解析 \`obj.revives\` 为座位号数组。
2. 说书人夜间回包循环（agents.cjs:986-1016）里，紧接 deaths 处理之后加：
   \`\`\`js
   if (rp && Array.isArray(rp.revives)) rp.revives.forEach(function (n) { const i = toIdx(n); if (i >= 0) { const r = E.revive(id, i); if (r && r.ok) applied.revives++; } });
   \`\`\`
   并让 \`didAct\`（agents.cjs:1017）把 revives 计入，避免「只复活了人」被判定为空转而触发 stall 提示。
3. 夜间提示词的输出模板（agents.cjs:513-517）加一行 \`"revives":[座位号（1 起）],\` 与说明「复活会立即改变存活状态与胜负，无需再写 deaths」。
4. 白天提示词（agents.cjs:548）同样加 \`"revives":[]\`，让说书人能手动修正。

### 六、agents.cjs —— 处决触发能力需要一个说书人回合（吟游诗人、和平主义者、造谣者）【中】

\`agents.cjs:1287-1302\`：\`nomFinish()\` 之后直接 \`setPhase('night')\`，中间没有任何说书人调用。应在此处插入一次「处决结算后」的说书人回合（或至少一个 prompt 片段）：
- 告知说书人「今天被处决的是 X 号，其真实角色为 Y（爪牙/镇民/外来者/恶魔）」；
- 要求它检查触发型能力：爪牙被处决 → 吟游诗人给全场（除吟游诗人本人与旅行者）挂 \`醉酒:直到明天黄昏\`；被处决者善良 → 和平主义者可裁定不死（配合第二条的 pendingExec）。
- 若不想新增阶段，最小改动是：在 \`buildStorytellerNightPrompt\` 里注入一段「【上一天处决回溯】上一白天被处决者=…；若为爪牙且有吟游诗人存活，本夜开始前必须给除吟游诗人外的所有存活玩家加醉酒标记」，并允许说书人在该轮只写 markers 不写 nextPhase。

### 七、agents.cjs —— 白天的「公开声明」登记（造谣者）【中】

1. 说书人白天回包加 \`claims:[{seat, text}]\`，由 agents.cjs 落成 \`E.setMarker(id, seat, '造谣声明:第N天:'+text)\`，并在 \`state.info\` 里给说书人自己留痕。
2. \`buildStorytellerNightPrompt\` 增加指令：读取标记里的 \`造谣声明:第N天\`，判断真伪；为真则当晚由说书人指定一名玩家死亡（写进 deaths），然后清除该标记。
3. 或者更轻的做法：在白天提示词里明确「当有玩家公开声明时，你必须用 markers 记下『造谣声明（第N天）：原文』，否则夜里你无法结算」，把责任压给说书人；但这样仍依赖 LLM 自觉，建议仍加 claims 结构化字段。

### 八、agents.cjs —— 驱魔人的跨条目否决（驱魔人）【中】

1. 夜间提示词（\`buildStorytellerNightPrompt\` 顺序表处理段，约 agents.cjs:503-519）加一条硬规则：
   「若驱魔人选中了恶魔：立刻给恶魔私聊 info『你是驱魔人的目标』；本夜跳过该恶魔在顺序表上的那一条（不唤醒、不结算其能力）；并在 markers 里给驱魔人记 \`驱魔人昨夜选择:N\`。下一次选人必须是别的座位（对比该标记）。」
2. 若希望程序层兜底，可在回包里加 \`skip:["恶魔"]\` 字段，由 agents.cjs 记录到 \`s.skippedThisNight\`，并在下一轮把它拼进提示词，避免说书人多轮之间忘掉「已经跳过恶魔」。

### 九、nightorder.json —— 基本无需改动

本批 10 个角色中，需要夜间条目的 7 个（驱魔人、旅店老板、赌徒、造谣者、侍臣、教授）在 \`other\` 表均已存在，侍臣在 \`first\` 与 \`other\` 两张表也都有；顺序上「驱魔人」在「小恶魔」之前、「教授」在「信息类角色行动开始」之前，符合规则。无需夜间行动的三位（吟游诗人、茶艺师、和平主义者、弄臣）不在表中，是正确的。
可选的加强：给 \`other\` 表中「造谣者」与「教授」各加一条注释性说明字段（如 \`note\`），提示说书人这两项分别依赖「白天声明」与「复活通道」，避免说书人在没有对应通道时静默跳过。

### 十、public/app.js —— 展示层（教授、免死）

1. 天亮播报目前只渲染「昨夜死亡」。需要同时渲染复活（\`s.dawnRevivals\`），否则玩家看不到有人复活，规则上「黎明宣布死亡与复活」不完整。
2. 免死导致的「处决但没人死」需要在投票结果面板里显示为「已处决但未死亡」，而不是沿用现有的「被处决」文案。
3. 若新增 \`markerUntil\`，面板上的标记最好带剩余时长（如「醉酒（至第 4 天黄昏）」），方便说书人与玩家核对。

### 十一、server.cjs —— API 透传

\`server.cjs:117\` 已透传 \`execute\`、\`:160\` 透传 \`nomFinish\`。新增的 \`revive\` / \`setMarker\` / \`clearMarker\` 必须一并加进 \`api\` 映射表，否则前端与调试接口无法调用。
